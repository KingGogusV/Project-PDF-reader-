# Requirements and acceptance trace

Created: **2026-10-02**. Updated: **2026-10-03 UTC**. Sources: the owner's original 12-part specification and subsequent [hosted-library upgrade](upgrade-scope.md). Original requirement IDs are retained. This is an acceptance record, not a claim that all requested features exist.

The first release should establish a safe, demonstrably functional universal reader. Native packaging is not a prerequisite for a shared browser implementation, but browser support on an OS must never be reported as a native application. Correctness, document fidelity, preservation, stability, security, and evidence take priority over feature count.

## Status and evidence rules

- **Planned**: requested and not yet assessed against completed implementation.
- **Implemented, not tested**: code exists, but the complete acceptance workflow is unverified.
- **Partially implemented**: state the supported subset and remaining limitation.
- **Verified on [environment]**: cite a completed test or runtime observation with environment and date.
- **Deferred / platform-limited**: record the reason and a specific backlog item where appropriate.
- **Failed**: retain the failure and reproduction until a fix is verified; never relabel a failing check as passed.

## Advanced scope and remaining work

Bounded page extraction/reordering/deletion/permanent rotation/merge, English OCR text export and invisible certificate signing now have real implementations and the tests listed above. They retain separate engine/license, safety and capability boundaries. The organizer creates page-only output and explicitly omits document-level metadata; it rejects structures it cannot preserve. OCR produces separate text without modifying the PDF. Signing verifies mathematical integrity without asserting certificate trust.

The remaining research/roadmap items are a dedicated insert/split workflow, compression, true redaction, document comparison, broad conversion/image export, PDF/A production, existing-content editing/find-replace, headers/footers/watermarks, automation workflows, searchable OCR PDF output, visible signature placement, and cryptographic trust/revocation/timestamp validation. An extract operation can produce a selected subset, but is not a completed batch-split workflow.

Each newly exposed capability still needs an explicit engine/license decision, safe-copy behavior, per-operation preservation tests and platform evidence. Redaction must remove underlying sensitive content; a painted rectangle is not redaction. Native package availability is evidenced by successful CI artifacts; their existence does not establish successful installation/runtime. Native filesystem integration, associations, share sheets, menus and updates require their own implementation and build/runtime verification.
