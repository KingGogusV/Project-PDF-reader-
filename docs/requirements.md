# Requirements and acceptance trace

Created: **2026-10-02**. Source: the owner's 12-part project specification supplied on this date. This is a concise acceptance record, not a claim that all requested features exist.

The first release should establish a safe, demonstrably functional universal reader. Native packaging is not a prerequisite for a shared browser implementation, but browser support on an OS must never be reported as a native application. Correctness, document fidelity, preservation, stability, security, and evidence take priority over feature count.

## Status and evidence rules

- **Planned**: requested and not yet assessed against completed implementation.
- **Implemented, not tested**: code exists, but the complete acceptance workflow is unverified.
- **Partially implemented**: state the supported subset and remaining limitation.
- **Verified on [environment]**: cite a completed test or runtime observation with environment and date.
- **Deferred / platform-limited**: record the reason and a specific backlog item where appropriate.
- **Failed**: retain the failure and reproduction until a fix is verified; never relabel a failing check as passed.

## Advanced scope deferred until the foundation is safe

The following are research/roadmap items, not first-release completion claims: permanent page organization (reorder/rotate/delete/extract/insert), merge/split, OCR/scanned-text recognition, compression, true redaction, document comparison, conversion/image export, PDF/A, content editing/find-replace, headers/footers/watermarks, and automation workflows.

Each requires an explicit architecture/engine/license decision, safe-copy behavior, per-operation round-trip/preservation tests, and platform evidence before exposure. Redaction must remove underlying sensitive content; a painted rectangle is not redaction. Certificate signing requires a separate trust/cryptography design. Native packages, OS file associations, share sheets, menus and update mechanisms remain platform-adapter work and must not be reported as available until built and tested.

## Final report checklist

Report concise actual outcomes: current state; implementation; verified platform/browser/device matrix; architecture decisions; exact checks; real measurements; incomplete/platform-limited features; next priorities; important changed files; repository/branch/write status; created commit IDs; verified push and CI status; and remaining uncommitted/local-only work. Do not use “works everywhere,” “fully working,” or “production ready” without corresponding evidence.
